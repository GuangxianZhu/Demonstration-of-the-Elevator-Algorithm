# 电梯调度算法演示

纯 HTML/CSS/JS 的电梯调度算法动画演示，无需安装、无需构建，双击即可运行。

## 怎么用

- **Windows**：双击 `start.bat`，会用默认浏览器打开 `index.html`。
- **其他系统**：直接用浏览器打开 `index.html`。
- **更新到最新版**：双击 `update.bat`，它会检查 `origin/main` 是否有新提交，有的话执行 `git pull --ff-only`（需要已安装 git，且本目录是 `git clone` 下来的）。

## 页面里有什么

1. **实时模拟**：和真实电梯一样，楼层外有 ▲/▼ 两个呼叫按钮（顶层只有 ▼、底层只有 ▲），乘客上车后再按目标楼层（轿厢内按钮，也可以手动按）。看电梯按所选算法移动、开关门。右侧显示请求队列、每一步的决策理由、累计移动层数、平均/最长等待时间，下方是楼层-时间轨迹图。
   - “制造饥饿场景”：顶楼有人等，同时中间几层不断有人按。分别用 SSTF 和 LOOK 跑一遍，对比顶楼那位等了多久。
2. **离线对比**：同一组请求（全部提前已知，类似操作系统课里的磁盘调度题）下，FCFS / SSTF / SCAN / LOOK 四种算法的路径图和总移动层数。可以先猜哪种最短再揭晓。
3. **原理速记**：四种算法的规则与优缺点。

## 算法简述

| 算法 | 规则 | 主要代价 |
| --- | --- | --- |
| FCFS | 按按钮被按下的顺序逐个去，途中不停 | 来回乱跑，路程最长 |
| SSTF | 永远去最近的请求，不管对方要上还是要下 | 远处请求可能饥饿 |
| SCAN | 沿一个方向扫到尽头再掉头，只顺路接同方向的外呼 | 尽头没人也要空跑 |
| LOOK | 前方没请求就掉头，只顺路接同方向的外呼 | 两端等待仍偏长 |

SCAN/LOOK 为什么只接同方向的外呼：电梯上行路过 5 楼，那里的人要下楼，接上他只会让他陪着先上去再下来，所以反方向的人等回程再接。现实中大多数电梯用的“集选控制”本质就是 LOOK。

简化假设：单台电梯、不考虑载重、乘客的目标楼层随机生成。离线对比部分假设乘客都已在车里按好目标楼层（全是内呼）。

## 文件

- `index.html` / `style.css` / `app.js`：页面、样式与动画
- `algorithms.js`：四种算法的纯函数实现（浏览器和 Node 通用）
- `tests/algorithms.test.js`：用教材经典磁盘调度例子和带方向外呼的场景校验算法，运行 `node tests/algorithms.test.js`
